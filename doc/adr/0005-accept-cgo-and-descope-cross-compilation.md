# 0005. CGO依存を許容し、クロスコンパイルをスコープ外とする

- **ステータス**: Accepted (承認済)
- **決定者**: プロジェクトチーム
- **作成日**: 2026-07-20

## コンテキスト (Context)
tree-sitterのコア実装はC言語で書かれており、現時点で実用的なGoバインディング（`go-tree-sitter` 系）はCGOを前提とする。これはAST-Diggerの主要な訴求点である「単一バイナリ配布」「クロスコンパイルの容易さ」とトレードオフの関係にある。論点は独立した2つの軸に分かれる。
- **論点A（単一バイナリ化の可否）**: ネイティブビルドであれば、CGOを使っても単一の実行ファイルは生成できる。ただし、真にゼロ依存の静的バイナリにするにはビルドフラグや環境面の追加対応が必要（macOSは完全な静的リンクが不可）。
- **論点B（クロスコンパイルの可否）**: CGOを有効にすると、`GOOS`/`GOARCH` だけで完結するGoのクロスコンパイル機構が機能しなくなる。ターゲットごとのCクロスコンパイラ（`zig cc` 等）の整備が必要になり、ビルド・CI構成が複雑化する。

## 決定 (Decision)
1. CGO依存を受け入れる。tree-sitterバインディングの利用を優先し、Pure-Go tree-sitter実装への依存は要求しない。
2. `GOOS`/`GOARCH` を切り替えたクロスコンパイルは、本プロジェクトのスコープ外とする。
3. Windows/macOS/Linux向けバイナリは、各プラットフォーム上でのネイティブビルド（`go build`）によって個別に生成する運用とする。
4. CGO依存箇所は `internal/parser` パッケージ内に閉じ込め、他レイヤー（`internal/db`, `internal/outline`, `cmd/ast-digger`）から直接参照させない設計とし、将来的なPure-Go実装への移行やクロスコンパイル要件の再検討に備える。

## 影響 (Consequences)
- **メリット**:
  - tree-sitterバインディングの実装が容易になり、初期リリースの開発速度を優先できる。
  - ビルド設計・CI構成がシンプルになる（クロスコンパイラの整備・保守が不要）。
- **デメリット**: リリース済みバイナリを、単一のCIジョブからビルドホスト以外のプラットフォーム向けに配布することができない。各ターゲットプラットフォームでのネイティブビルド環境（例: GitHub Actionsの `windows-latest` / `macos-latest` / `ubuntu-latest` ランナー）を用意する運用コストが発生する。
- **リスク**: 将来的にクロスコンパイルの必要性が高まった場合（リリース自動化要求等）、`zig cc` 導入やPure-Go tree-sitter実装への移行という追加作業が発生する。

## 検討した選択肢 (Considered Alternatives)
- **`zig cc` 等のクロスコンパイラを初期実装から整備する**
    - Pros: 単一のCIパイプラインで全プラットフォーム向けバイナリを生成できる。
    - Cons: 初期リリースの優先度に対してビルドパイプラインの複雑化コストが見合わない。
    - Result: Rejected（将来の再検討条件として記録）。
- **Pure-Go tree-sitter実装の調査を先行させる**
    - Pros: CGO依存を根本的に回避できる。
    - Cons: 現時点で実用十分なPure-Go実装が存在しない。
    - Result: Rejected（拡張ポイントとして設計上の余地は残す。決定4参照）。
