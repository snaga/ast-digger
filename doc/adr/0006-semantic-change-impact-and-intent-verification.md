# 0006. ASTステートメント・循環複雑度による意味的変更規模判定と意図充足度評価

- **ステータス**: Accepted (承認済)
- **決定者**: プロジェクトチーム
- **作成日**: 2026-10-21

## コンテキスト (Context)
スペック駆動開発（SDD）や AI エージェントによる自律コーディングにおいて、変更規模を「意味のある単位」に最小化し、差分の肥大化やコンテキスト汚染を防止したいという要求がある。

従来の物理行数（Git diff の `+` / `-` 行数）による画一的な制限（例: 「1コミット100行以内」）には以下の課題が存在した：
1. **ノイズの誤検知**: 空行、インデント修正、コードコメントの加筆、型定義のインポート順序変更など、ロジックに影響を与えない変更でも容易に上限を超過し、不当なリジェクトが発生する。
2. **意味的複雑さの無視**: 物理行数は少なくてもネストした制御構文（`if`, `for`, `switch`）が大量に導入される複雑な変更と、定数宣言が並んでいるだけの変更を区別できない。
3. **外部ドキュメントとの同期不全**: 大規模な変更やモジュール境界を跨ぐ変更が行われた際、コード自体の行数制限だけでなく、コードコメント（Docstring）や外部ドキュメント（設計書、モジュール解説、ADR 等）が同期されているかを確認・惹起する仕組みが存在しなかった。

## 決定 (Decision)
以下のアーキテクチャ方針に基づき、新サブコマンド `change-impact` を設計・実装する：

1. **AST構文ステートメント & 循環複雑度差分（Cyclomatic Delta）による判定**:
   - 物理行数ではなく、各言語の Tree-sitter AST 構文ノード（文・宣言）の純増減（Statements Delta）および制御分岐ノード（`if`, `for`, `switch`, `catch`, `&&`, `||` 等）の増減（Complexity Delta）を計測する。
   - 合計変更規模から 4 段階のインパクトレベル（`MINOR`, `MODERATE`, `SIGNIFICANT`, `EXTREME`）を算出する。
2. **Tree-sitter メモリ上バイト列パース（`ParseBytes`）の共通化**:
   - Git コミット時点（`git show base:file`）と作業ツリーのソースコードを一時ファイルに書き出すことなく、メモリ上の `[]byte` のまま Tree-sitter で直接解析できるよう全パーサーに `ParseBytes` を導入する。
3. **差分行とシンボルマッピングによる Docstring 監査**:
   - Git unified diff の変更行番号集合とシンボルの行範囲を O(1) で突き合わせ、影響を受けたシンボルを特定する。
   - 削除されたシンボルは Docstring 監査から除外し、残存・新規追加シンボルの可視性（Public/Private）に応じた Docstring 充足率を評価する。
4. **特定ファイル配置に依存しない汎用外部ドキュメント同期アドバイザリー**:
   - `internal/*/README.md` などの特定プロジェクト固有のファイル存在を前提とせず、モジュール境界の構造変化やクロスモジュール変更を動的に検知し、設計意図を維持するための外部ドキュメントや ADR の更新・作成を促す汎用アドバイザリーを生成する。
5. **AI エージェントの自己修復性を担保する先行レポート出力 + 終了コード 2**:
   - ガードレール検証（`--max-statements`、`--fail-on-missing-doc`）において、違反時でも即座にプロセスを落とさず、まず標準出力（stdout）に完全な解析レポート（テキストまたは JSON）を出力した後に標準エラー出力へ通知し、終了コード `2`（パラメータ/検証エラー）を返却する。
   - これにより、エージェントは終了コード 2 を検知した瞬間に標準出力をパースし、違反原因（欠落 docstring のシンボル名等）を即座に自律修正できるようにする。

## 影響 (Consequences)
- **メリット**:
  - 空行・コメントの追記やフォーマッタ適用によってガードレールが誤検知される問題が完全に解消される。
  - AI コーディングエージェントの作業単位が「意味のある規模」で自律制御可能になり、Docstring 欠落やドキュメント不整合の発生を早期防止できる。
  - ガードレール違反時に先行出力される構造化 JSON レポートにより、自己修復ループが高速かつ安定して動作する。
- **デメリット**:
  - Tree-sitter 未対応の言語については AST 構文解析が行えず、行ベースの簡易フォールバックとなる。
  - Git コマンドが利用できない環境では `change-impact` を実行できない（Git リポジトリ内での動作を前提とする）。

## 検討した選択肢 (Considered Alternatives)
- **選択肢1: 物理行数（diff 行数）によるハードリミット**
  - 結果: Rejected。コメント追加やフォーマット変更で容易に誤作動し、開発体験およびエージェントの自律作業を阻害するため。
- **選択肢2: 特定ドキュメントファイル（`internal/<module>/README.md` 等）の存在を強制する**
  - 結果: Rejected。AST-Digger は汎用的な Agent-Native CLI ツールであり、特定のリポジトリ設計ルールやディレクトリ規約を強制すべきではないため。モジュール境界変化とクロスモジュール検知に基づくアドバイザリーメッセージ出力方式を採用。
